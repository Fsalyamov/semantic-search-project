# Рабочий документ: семантический поиск товаров

## Цель проекта

Построить MVP поиска товаров по текстовому запросу, сравнить TF-IDF и векторный поиск, проверить улучшения и сформулировать рекомендацию бизнесу.

## Неделя 1. Данные и EDA

Исходный каталог содержит 200000 строк и 174427 уникальных карточек imt_id. Одна карточка может объединять несколько артикулов nm_id.

В тренировочной разметке — 11453 пары «запрос — товар» и 700 запросов. В тестовой — 4866 пар и 300 запросов. Все товары из разметки присутствуют в исходном каталоге. Пересечений query_id и нормализованных текстов запросов между train и test нет.

Пустые описания встречаются в 28,75% строк, названия — в 0,35%. Медиана длины непустого описания — 53 слова, 95-й процентиль — 188 слов.

### Принятые решения

- Для MVP выбраны категории «Одежда» и «Обувь».
- Единица поиска — карточка imt_id, поскольку с ней связана разметка.
- При дедупликации предпочтение отдаётся строке с названием, затем с наиболее длинным описанием. При равенстве используется nm_id.
- После дедупликации удалены 113 карточек без названия и описания. Осталось 48376 карточек.
- Очистка нормализует пробелы, удаляет HTML-теги и служебные символы. Числа и обозначения моделей сохраняются.
- Базовый product_text состоит из названия, предметной категории и описания.

## Неделя 2. Базовые модели

Лексический baseline — TF-IDF с ngram_range=(1, 2) и max_features=100000. Векторизатор обучен на подготовленном каталоге из 48376 карточек.

Семантическая модель — intfloat/multilingual-e5-small без дообучения. Используются префиксы query: и passage:, нормализованные векторы размерности 384 и лимит 512 токенов. В базовом шаблоне лимит превышали 53 карточки из 4256.

### Каталог оценки

Каталог оценки ограничен пулом асессоров: 4256 карточек. Все товары тренировочной разметки входят в этот каталог. TF-IDF не переобучается: из полной матрицы выбираются нужные строки.

На одинаковых 100 запросах NDCG@10 вырос с 0,0720 на полном каталоге до 0,4634 на пуле оценки. Модель при этом не менялась. В полном каталоге поиск чаще возвращал неразмеченные товары, получавшие 0 при оценке. Например, из десяти найденных жилетов оценён только один. Поэтому первая цифра отражала и качество поиска, и покрытие разметки.

У всех десяти жилетов одинаковый скор. При таких совпадениях порядок определяется расположением строк каталога, а не степенью соответствия запросу.

### Правила расчёта метрик

- Golden-сет — фиксированные 700 запросов train с их разметкой.
- K: 1, 3, 5, 10.
- Релевантными для бинарных метрик считаются оценки 2 и 3.
- NDCG использует всю шкалу с gain = 2^relevance − 1.
- Неразмеченные товары получают оценку 0.
- MRR@K учитывает первую релевантную позицию только в пределах K.

В разметке нет нулевых оценок, а у каждого запроса ровно один товар с оценкой 3. Это похоже на подбор товаров вокруг одного целевого примера.

При пороге 1 релевантными становятся все размеченные товары — в среднем 16,36 на запрос. При пороге 3 остаётся один. Выбран порог 2: он исключает слабые совпадения, но учитывает несколько подходящих товаров. В среднем их 2,57 на запрос.

У четырёх запросов, или 0,57%, размечен только один товар. Для них Recall показывает его попадание в топ-K, а NDCG дополнительно учитывает позицию.

На всех 700 запросах E5-small превосходит базовый TF-IDF. При этом TF-IDF получает NDCG@10 = 0,4364 при Precision@1 = 0,0729: NDCG учитывает десять позиций и положительный вклад товаров с оценкой 1. Для бинарных метрик такие товары нерелевантны. Поэтому качество оценивается по нескольким метрикам.

## Неделя 3. Эксперименты

Первые три эксперимента сравнивались с базовым E5-small. После ревью добавлены проверки бренда, словаря TF-IDF и последовательные изменения гибрида. Все сравнения выполнены на одном golden-сете с одинаковыми порогом и K.

### Эксперимент 1. Добавление бренда

**Гипотеза:** бренд в тексте поможет различать товары в запросах с названием бренда. Основание — ошибки обоих baseline на таких запросах при ручном просмотре.

**Изменение:** product_text = название + категория + бренд + описание.

**Результат:** NDCG@10 вырос с 0,4741 до 0,5633, Recall@10 — с 0,5942 до 0,7674.

**Вывод:** гипотеза поддерживается результатами. Улучшились все рассчитанные метрики.

После ревью запросы разделены по наличию названия бренда из каталога: 222 с найденным брендом и 478 без найденного бренда.

В первой группе NDCG@10 вырос с 0,3919 до 0,6670, Recall@10 — с 0,4129 до 0,9269. Во второй группе NDCG@10 вырос с 0,5123 до 0,5151. Основной прирост пришёлся на запросы с брендом. Разделение приблизительное: опечатки и альтернативные написания не учитывались.

Для равных условий бренд добавлен и в TF-IDF. Его NDCG@10 вырос с 0,4364 до 0,5144, Recall@10 — с 0,3137 до 0,5424. E5 с брендом сохранил преимущество по всем рассчитанным метрикам.

Проверен словарь TF-IDF. В полном каталоге с брендом найдено 36220 униграмм и 266419 биграмм — всего 302639 признаков. Ограничение max_features оставляет 100000 наиболее частотных признаков, а не признаков с максимальным IDF.

Из 206 уникальных токенов брендов найденных брендовых запросов в исходном словаре было 104, в словаре с брендом — 200. Шесть отсутствующих токенов встречаются в каталоге всего один-два раза.

### Эксперимент 2. Удаление описания

**Гипотеза:** исключение описаний уменьшит влияние рекламного текста, обнаруженного при EDA.

**Изменение:** product_text = название + категория, без описания и бренда.

**Результат:** NDCG@10 снизился с 0,4741 до 0,2573, Recall@10 — с 0,5942 до 0,2635.

**Вывод:** гипотеза отклонена. Вместе с рекламным текстом удаляются полезные характеристики.

Описание есть у 77,51% карточек пула оценки и у 37,39% полного каталога. Поэтому на полном каталоге вклад описания может быть меньше.

### Эксперимент 3. Гибридный поиск

**Гипотеза:** объединение лексического и семантического ранжирования позволит использовать преимущества обоих подходов.

**Изменение:** объединение рангов базовых TF-IDF и E5-small методом RRF с параметром 60. В исходном варианте используются все 4256 карточек и равные вклады методов.

**Результат:** NDCG@10 вырос с 0,4741 до 0,5119, но Recall@10 снизился с 0,5942 до 0,5504, MRR@10 — с 0,5044 до 0,3950.

**Вывод:** общего улучшения нет. Исходный гибрид не выбран для финального теста.

После ревью проверены три последовательных изменения:

1. Ограничение глубины до top-50 при равных вкладах. NDCG@10 снизился с 0,5119 до 0,5081. Само ограничение глубины качество не улучшило.
2. Веса 0,3 для TF-IDF и 0,7 для E5 при той же глубине. NDCG@10 вырос до 0,5101, MRR@10 — с 0,3925 до 0,4508. Увеличение вклада E5 улучшило результат относительно равных весов.
3. Добавление бренда в тексты обоих методов при сохранении глубины и весов. NDCG@10 вырос до 0,6105, Recall@10 — до 0,7606, MRR@10 — до 0,6530. Бренд улучшил и гибридный поиск.

В среднем 91,44% товаров получают нулевой скор базового TF-IDF. В исходном RRF они всё равно вносят вклад, а их взаимный порядок определяется строками каталога. Top-50 сокращает число кандидатов, но не гарантирует исключения нулевых скоров.

### Сравнение на golden-сете

| Подход | NDCG@10 | Recall@10 | MRR@10 | Precision@5 |
|---|---:|---:|---:|---:|
| TF-IDF | 0,4364 | 0,3137 | 0,1618 | 0,0777 |
| E5-small | 0,4741 | 0,5942 | 0,5044 | 0,2246 |
| TF-IDF + бренд | 0,5144 | 0,5424 | 0,3592 | 0,1571 |
| E5-small + бренд | 0,5633 | 0,7674 | 0,6867 | 0,2711 |
| E5-small без описания | 0,2573 | 0,2635 | 0,2360 | 0,0871 |
| RRF по всему каталогу | 0,5119 | 0,5504 | 0,3950 | 0,1851 |
| RRF top-50 | 0,5081 | 0,5457 | 0,3925 | 0,1840 |
| RRF top-50 с весами | 0,5101 | 0,5706 | 0,4508 | 0,2123 |
| RRF top-50 с весами и брендом | 0,6105 | 0,7606 | 0,6530 | 0,2663 |

Одного лидера по всем метрикам нет. Гибрид с брендом лучше по NDCG@10. E5 с брендом лучше по Recall@10, MRR@10 и Precision@1: 0,5743 против 0,5357 у гибрида.

Для сценария, где важнее первый подходящий результат, сохраняю выбор E5 с брендом. Гибрид рассматриваю как альтернативу для сравнения в пилоте.

### Финальный тест

По итогам первоначальных экспериментов до тестирования выбран E5-small с брендом. На 300 тестовых запросах получены:

- NDCG@10 — 0,5696.
- Recall@10 — 0,7828.
- MRR@10 — 0,6477.
- Precision@5 — 0,2467.
- Precision@1 — 0,5400.
- HitRate@10 — 0,8700.

Проверенная конфигурация E5 с брендом не менялась. Дополнительные эксперименты после ревью выполнены на golden-сете. Новые варианты гибрида на test не оценивались, поэтому приведённые тестовые метрики относятся только к E5 с брендом.

### MLflow

Эксперимент: semantic_search_project.

Для девяти конфигураций на golden-сете используются имена запусков:

- tfidf_baseline;
- e5_baseline;
- e5_brand;
- e5_short;
- tfidf_e5_rrf;
- tfidf_brand;
- tfidf_e5_rrf_top50;
- tfidf_e5_rrf_top50_weighted;
- tfidf_e5_brand_rrf_top50_weighted.

Тестовая оценка сохраняется отдельно: e5_brand_final_test.

Сохранены параметры, метрики, таблицы по запросам, сводные таблицы и использованные наборы разметки. В e5_brand дополнительно сохранены график и общая таблица сравнения девяти конфигураций.

Метрика mrr содержит MRR@10; ограничение указано параметром mrr_cutoff=10.

Проверка check_mlflow.py с --min-runs 10 пройдена. На момент проверки найдено 22 успешных запуска, включая повторные выполнения. Скрипт подтвердил наличие обязательных метрик и параметров; содержимое артефактов он не проверяет.

## Качественный анализ

- «Рубашки с карманами»: категория выдачи соответствует запросу, но наличие карманов нельзя проверить по названиям.
- «Бежевые футболки»: отдельное поле цвета не включено в текст. Одна карточка может содержать описание нескольких цветовых вариантов.
- «Классические джинсовые джинсы»: среди результатов есть названия с признаками классических джинсов, однако они не размечены для запроса.

Разбор относится к E5 с брендом. Во всех трёх примерах топ-5 не имеет оценок. Это не доказывает нерелевантность выдачи и показывает необходимость дополнительной разметки.

## Ограничения

- Запросы синтетические, разметка неполная, а каталог оценки меньше полного.
- Неразмеченные товары получают 0, хотя могут подходить запросу.
- В пуле оценки описания встречаются чаще, чем в полном каталоге.
- Длинные тексты обрезаются по лимиту модели.
- Поиск на уровне карточки не всегда различает варианты по цвету и размеру.
- Ограничение словаря TF-IDF исключает часть редких слов брендов.
- Равные скоры приводят к зависимости порядка выдачи от расположения строк.
- Golden-сет многократно использовался для сравнения конфигураций. Новые гибриды требуют проверки на независимой выборке.
- Тестовая оценка выполнена только для E5 с брендом.
- Производительность под нагрузкой и влияние на продажи не проверялись.

## Рекомендация бизнесу

Рекомендую пилот E5-small с названием, категорией, брендом и описанием. На подготовленной разметке этот вариант превосходит TF-IDF даже при одинаковом составе текста.

Гибрид с брендом стоит включить в пилот как альтернативу: он лучше по NDCG@10, но уступает по качеству первой позиции и MRR@10. Полную замену действующего поиска следует рассматривать после проверки на реальных запросах.

Точные условия — цвет, размер, бренд и другие характеристики — требуют дополнительного контроля: семантическая близость не гарантирует их соблюдения.
