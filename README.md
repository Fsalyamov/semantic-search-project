# Семантический поиск товаров

MVP поиска товаров по текстовому запросу. В проекте сравниваются TF-IDF, семантический поиск на `intfloat/multilingual-e5-small` и гибридный поиск RRF.

Работа выполнена для категорий «Одежда» и «Обувь». Подготовленный каталог содержит 48376 карточек, каталог оценки — 4256 карточек из пула асессоров.

## Результаты

На golden-сете из 700 запросов сравнивались 9 конфигураций.

| Подход | NDCG@10 | Recall@10 | MRR@10 | Precision@5 |
|---|---:|---:|---:|---:|
| TF-IDF | 0,4364 | 0,3137 | 0,1618 | 0,0777 |
| E5-small | 0,4741 | 0,5942 | 0,5044 | 0,2246 |
| TF-IDF + бренд | 0,5144 | 0,5424 | 0,3592 | 0,1571 |
| E5-small + бренд | 0,5633 | 0,7674 | 0,6867 | 0,2711 |
| E5-small без описания | 0,2573 | 0,2635 | 0,2360 | 0,0871 |
| RRF по всему каталогу | 0,5119 | 0,5504 | 0,3950 | 0,1851 |
| RRF top-50 | 0,5081 | 0,5457 | 0,3925 | 0,1840 |
| RRF top-50 с весами | 0,5101 | 0,5706 | 0,4508 | 0,2123 |
| RRF top-50 с весами и брендом | 0,6105 | 0,7606 | 0,6530 | 0,2663 |

В вариантах с разными весами вклад TF-IDF равен 0,3, E5 — 0,7. Параметр RRF равен 60. В последнем варианте бренд добавлен в тексты обоих методов.

Одного лидера по всем метрикам нет:
- Гибрид с брендом показал лучший NDCG@10 — 0,6105.
- E5-small с брендом лучше по Recall@10, MRR@10 и Precision@1. Подходящий товар на первой позиции найден в 57,43% запросов против 53,57% у гибрида.
- При одинаковом составе текста E5 с брендом превосходит TF-IDF с брендом по всем рассчитанным метрикам.
- Удаление описания ухудшило качество.

Для сценария, где важнее первый подходящий результат, выбран E5-small с текстом:
`название + предметная категория + бренд + описание`.

Результаты этой конфигурации:

| Набор | Запросов | NDCG@10 | Recall@10 | MRR@10 | Precision@5 |
|---|---:|---:|---:|---:|---:|
| Golden-сет, train | 700 | 0,5633 | 0,7674 | 0,6867 | 0,2711 |
| Финальный test | 300 | 0,5696 | 0,7828 | 0,6477 | 0,2467 |

Дополнительные проверки после ревью выполнены на golden-сете. Тестовые результаты относятся только к E5 с брендом; новый гибрид на test не оценивался.

Порог релевантности для Precision, Recall, MRR и HitRate — 2. Проверяемые K: 1, 3, 5, 10. NDCG использует всю шкалу оценок с gain = 2^relevance − 1. Неразмеченные товары получают оценку 0.

## Файлы проекта

- `semantic_search_project.ipynb` — подготовка данных, EDA, модели, эксперименты, оценка и выводы.
- `semantic_search_project_workbook.md` — рабочий документ с решениями и результатами.
- `check_mlflow.py` — проверка эксперимента MLflow.
- `requirements.txt` — зафиксированные зависимости.
- `.gitignore` — исключения для данных, секретов и локальных файлов.

## Требования

- Python 3.12.5.
- Git.
- VS Code с расширениями Python и Jupyter либо другое окружение для запуска ноутбуков.
- Интернет для установки пакетов, загрузки модели и доступа к S3 и MLflow.
- Учебные параметры доступа к S3 и работающий сервер MLflow.

## Установка

Команды ниже предназначены для PowerShell в Windows.

```powershell
git clone https://github.com/Fsalyamov/semantic-search-project.git
cd semantic-search-project
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

## Настройка доступа

Создайте файл `.env` в корне проекта:

```dotenv
AWS_ACCESS_KEY_ID=<ключ доступа к S3>
AWS_SECRET_ACCESS_KEY=<секретный ключ S3>
S3_ENDPOINT_URL=https://storage.yandexcloud.net
S3_SOURCE_BUCKET=<имя исходного бакета>
MLFLOW_TRACKING_URI=<полный адрес учебного MLflow с https://>
MLFLOW_TRACKING_USERNAME=<логин MLflow>
MLFLOW_TRACKING_PASSWORD=<пароль MLflow>
MLFLOW_S3_ENDPOINT_URL=https://storage.yandexcloud.net
```

Замените значения в угловых скобках параметрами из учебной среды. Для сохранения артефактов необходим доступ на запись в бакет, используемый MLflow.

Файл `.env` не должен попадать в репозиторий.

## Данные

Используются четыре файла:
- `wb_products_raw_sample.parquet` — исходный каталог.
- `wb_products_dedup.parquet` — список карточек пула асессоров.
- `queries_synthetic_train.parquet` — тренировочная разметка и golden-сет.
- `queries_synthetic_test.parquet` — финальная тестовая разметка.

Ноутбук скачивает необходимые файлы из S3 в `data/`, если их ещё нет. Доступ к исходным данным предоставляется учебной платформой. Публичный репозиторий не содержит данных и учётных данных для их загрузки.

## Запуск ноутбука

1. Откройте папку проекта в VS Code.
2. Откройте `semantic_search_project.ipynb`.
3. Выберите ядро `.venv` с Python 3.12.5.
4. Выполняйте ячейки последовательно сверху вниз.

В ноутбуке выполняются:
- загрузка и проверка данных;
- EDA и подготовка каталога;
- построение TF-IDF и эмбеддингов E5-small;
- оценка базовых методов;
- эксперименты с брендом, составом текста и RRF;
- отдельная оценка запросов с найденным брендом и без него;
- проверка словаря TF-IDF и влияния ограничения числа признаков;
- сравнение гибридов с разной глубиной слияния, весами и составом текста;
- тестовая оценка E5-small с брендом;
- сохранение результатов в MLflow;
- качественный анализ и итоговые выводы.

При первом запуске модель загружается с Hugging Face. Эмбеддинги сохраняются в `artifacts/`. Повторное выполнение ячеек расчёта эмбеддингов пересчитывает их.

Тестовый блок управляется переменной `RUN_FINAL_TEST_EVAL`. Для полного воспроизведения используйте `True`: последующие ячейки сохраняют тестовые результаты. Не используйте test для подбора параметров.

Повторное выполнение ячеек логирования создаёт новые запуски MLflow. Для просмотра готовых результатов достаточно сохранённых выводов ноутбука.

## MLflow

Название эксперимента: `semantic_search_project`.

Для девяти конфигураций на golden-сете используются следующие имена запусков:
- `tfidf_baseline`;
- `e5_baseline`;
- `e5_brand`;
- `e5_short`;
- `tfidf_e5_rrf`;
- `tfidf_brand`;
- `tfidf_e5_rrf_top50`;
- `tfidf_e5_rrf_top50_weighted`;
- `tfidf_e5_brand_rrf_top50_weighted`.

Тестовая оценка сохраняется отдельно: `e5_brand_final_test`.

Запуски содержат параметры, метрики, таблицы результатов и копию оценочной разметки. График и общая таблица сравнения дополнительно сохранены в `e5_brand`.

Метрика `mrr` соответствует MRR@10; ограничение указано параметром `mrr_cutoff=10`.

В эксперименте могут быть повторные запуски с одинаковыми именами после повторного выполнения ноутбука.

Проверка из корня проекта:

```powershell
.\.venv\Scripts\python.exe check_mlflow.py semantic_search_project --env-file .env --min-runs 10
```

Скрипт проверяет наличие эксперимента, минимальное число успешных запусков и обязательные метрики и параметры. Полноту артефактов нужно проверять отдельно в MLflow.

Для подключения сервер MLflow должен быть включён в учебной платформе.

## Ограничения

- Разметка синтетическая и неполная. Неразмеченные товары могут подходить запросу, но получают 0 при оценке.
- Каталог оценки меньше полного каталога. Полученные метрики нельзя напрямую переносить на промышленный поиск.
- Описания есть у 77,51% карточек пула оценки и у 37,39% полного каталога. Польза описаний на полном каталоге может быть меньше.
- E5-small ограничен 512 токенами. В базовом шаблоне лимит превышали 1,25% карточек.
- Ограничение TF-IDF в 100000 признаков исключает часть редких слов брендов.
- При равных скорах порядок зависит от расположения строк каталога. Ограничение глубины RRF не исключает попадания товаров с нулевым TF-IDF-скором.
- Дополнительные варианты гибрида проверены только на golden-сете, который использовался для выбора конфигураций.
- Скорость под нагрузкой и влияние на продажи не измерялись.

## Рекомендация

Рекомендуется пилот E5-small с названием, категорией, брендом и описанием. Гибрид с брендом стоит проверить как альтернативу: он лучше по NDCG@10, но уступает по первой позиции и MRR@10.

Следующие шаги — собрать реальные запросы, дополнить разметку, сравнить решения на независимой выборке, добавить фильтры по характеристикам и измерить задержки на полном каталоге. Решение о внедрении следует принимать после A/B-теста.

Streamlit-приложение не реализовано: это дополнительная часть задания.
